# Bridge · Available Routes layout and scrollbar

HEAD at start and end: `0f6f59c` (changes uncommitted). Modified: `index.html` (CSS only, appended to the existing `brg-modern-ui` style block, all rules scoped to `#page-bridge`).

## Cause
- `#bridge-routes-inner` was capped at `max-height:72vh` (648px at 900px high, 553px at 768px) while the card was 722px / 654px, so the columns never ended together.
- `scrollbar-width:thin` on that container makes Chromium ignore the `::-webkit-scrollbar` rules, so the browser's default light scrollbar was drawn.

## Changes
- Desktop (>=1080px): the routes panel stretches to the card's row height (`align-self:stretch` + `contain:size`, so it never defines the row). Only the list scrolls; the "Available Routes" header is sticky with a soft fade. The panel gets the same surface as the main card.
- Applies only while the panel lists routes (loading, empty and error included); the execution steps view is untouched.
- Scrollbar: 4px, transparent track, rounded thumb, no arrows, `#343E4C`-based (dark) / soft slate (light), stronger on hover, 4px stable gutter so cards never shift. Firefox gets `scrollbar-width:thin` with the same colours. No JS.
- Tablet / mobile (<1080px): no inner scroll and no max height; the page scrolls naturally and the header is not sticky.

## Measured (headless Chromium, simulated routes, no funds)
| Viewport | Card | Panel (was) | Panel (now) |
|---|---|---|---|
| 1440x900, 1/3/6/9 routes | 722 | 145 / 400 / 648 / 648 | 722 |
| 1366x768, 6 routes | 654 | 553 | 654 |
| 1100x800, 6 routes | 654 | 576 | 654 |
| 900x900 / 390x844 | stacked | inner scroll | natural page scroll |

Top edges match (y=122). Scrollbar width 4px. No horizontal overflow, no console errors. A re-render of the routes (auto quote refresh path) keeps the scroll position and the selected route.

## Not touched
Route cards and their markup, selection (card body and Select button), discovery/ranking, CCTP/LI.FI, readiness, execution, history, Help, other pages.

## Tests
Full suite: 136 failing tests before and after, same list (one unrelated x402 signing test failed once in a single run and passed in 3 isolated runs and a full re-run). Production build passes (`public/index.html` regenerated by the build was reverted).

## Limits
No real quotes or transactions were exercised; routes were injected through the existing render/select functions. Browsers without `:has()` keep the previous panel sizing. Safari/Firefox were not run here.
